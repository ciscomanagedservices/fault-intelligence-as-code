# ia-explorer

Generate and open an interactive HTML explorer for published Intelligence Artifacts. Output goes to `docs/index.html` for GitHub Pages serving.

## Prerequisites

- `intelligence-artifacts/index.json` exists (generated by `ia-publish`)
- Agent must have `read_file`, `run_in_terminal` tools
- Git repository must be initialized (for auto-commit/push step)

## Procedure

### Step 1 — Read Index

Read `intelligence-artifacts/index.json`. If the file does not exist, tell the user:

> "No index.json found. Run `ia-publish` first to publish artifacts and generate the index."

Parse the JSON and note `stats.total`. If `total` is 0, warn:

> "The index exists but contains no artifacts. Publish artifacts with `ia-publish` first."

### Step 2 — Generate Explorer HTML

Run the explorer generator script:

```bash
python .opencode/skills/ia-explorer/generate_explorer.py
```

This reads the template from `.opencode/skills/ia-explorer/template.html`, inlines the index JSON, and writes `docs/index.html`. The `docs/` directory is created automatically if it does not exist.

The HTML file is generated fresh on every invocation to pick up the latest index data.

### Step 3 — Open in Browser

Open the generated file in the user's default browser:

```bash
# Windows
start docs/index.html

# macOS
open docs/index.html
```

### Step 4 — Auto-commit and Push

Commit `docs/index.html` to the current branch and push to origin:

```bash
git add docs/index.html
git commit -m "docs: regenerate explorer ($(date -u +%Y-%m-%d))"
git push
```

If the push fails because the local branch has no upstream, set it:

```bash
git push -u origin <CURRENT_BRANCH>
```

If there are no changes to `docs/index.html` (i.e., `git status` shows it clean), skip the commit step and note:

> "Explorer HTML is already up to date — no commit needed."

> **Note:** When `ia-explorer` is invoked as part of `ia-publish` (Step 3c), skip this auto-commit step — the explorer output will be included in the publish commit instead.

### Step 5 — Confirm

Tell the user the explorer is open and summarize what it contains:

> "Explorer updated at **docs/index.html** with **N** artifacts across **M** groups. Committed and pushed to current branch."

## Explorer Features

The generated HTML includes:

1. **Syslog regex search** — user pastes a raw syslog line; JS runs each FS `regex_patterns[]` against it and displays all matching artifacts grouped as match sets
2. **Keyword search** — case-insensitive substring match across name, description, tags, mnemonics, component
3. **Search by ID** — exact or prefix match on `artifact.id` (e.g., `FS000005`, `RAW000006`, `RG000005`)
4. **Faceted filters** — Platform, Component, Severity, Type (FS/RG/RAW) — populated from stats, filters AND together
5. **Coverage matrix** — collapsible platform × component grid with gap highlighting
6. **Artifact detail expansion** — click to expand:
   - Full description
   - Regex patterns with copy button (FS only)
   - **Message samples** — one per event, amber left-border monospace block (FS only)
   - Syslog mnemonics
   - Symptoms (RG only)
   - Tags and platforms
   - Linked artifacts with scroll-to navigation
   - Open design question count
   - File path with **View on GitHub** hyperlink (shown when `repo_url` is present in index.json)

## GitHub URL Integration

The explorer constructs GitHub artifact links using `repo_url` and `default_branch` from `index.json`. These fields are populated by `generate_index.py` via `git remote get-url origin` and `git symbolic-ref` detection. If `repo_url` is empty, the "View on GitHub" link is hidden.

## Design Direction

- Dark industrial theme (charcoal `#0d1117` base)
- Monospace for syslog/regex/sample content, geometric sans for headings
- Dense layout — data-first, no wasted whitespace
- Sharp edges, thin borders, no rounded cards
- Python→JS regex translation: replace `(?P<` with `(?<`
