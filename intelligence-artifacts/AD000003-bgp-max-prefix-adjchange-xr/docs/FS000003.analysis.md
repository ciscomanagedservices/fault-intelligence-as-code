## Condition Logic Rationale

This is a single-event fault signature, so `logic: "E1"` is sufficient and
`logic_lookback_time` remains `0`. The syslog itself is definitive because it
already states the remote peer sent a BGP notification for maximum prefixes.

## Detection Coverage Assessment

- **Catches:** Neighbor-sent IOS XR BGP ADJCHANGE syslogs for maximum-prefix limit reached
- **Misses:** Cases where the peer enforces max-prefix but the local device logs a different string, or cases detected only through counters / telemetry without the syslog
- **False positive risk:** Low, because the regex is tightly anchored to the exact reason text and required fields `(VRF, AS)`

## Assumptions

1. The exact reason text `maximum number of prefixes reached` is stable across the target IOS XR releases.
2. The same neighbor IP / VRF / AS tuple appears in the recovery `Up` syslog and can be used for clear-event correlation.
3. The remote AS extracted from the syslog is sufficient for downstream context; no local ASN extraction is needed in the signature.
