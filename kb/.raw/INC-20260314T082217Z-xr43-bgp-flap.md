# INC-20260314T082217Z — BGP Session Flap to Upstream PE (xr-43)

## Summary

Edge router **xr-43** (Cisco ASR-9904) experienced repeated BGP session flaps to upstream provider ISP-A (peer 198.51.100.1, AS 65001) over a 47-minute window. Traffic failed over to secondary path via xr-44 within BFD detection time (50ms), but the flapping caused route churn visible to downstream branches.

## Timeline

| Time (UTC) | Event |
|------------|-------|
| 08:22:17 | First BGP NOTIFICATION received — Hold Timer Expired |
| 08:22:18 | BFD session DOWN on GigabitEthernet0/0/0/1 |
| 08:23:02 | BGP session re-established |
| 08:27:41 | Second flap — same peer, same NOTIFICATION |
| 08:35:19 | Third flap — NOC escalates to SEV-2 |
| 08:48:00 | TAC engaged; identified CRC errors on interface |
| 09:02:00 | ISP-A confirms degraded optic on their PE side |
| 09:09:14 | ISP-A replaces SFP; session stabilizes |
| 09:22:00 | 15-minute stability confirmed; incident resolved |

## Symptoms

- Syslog: `%ROUTING-BGP-5-ADJCHANGE: neighbor 198.51.100.1 Down - Hold Timer Expired`
- Syslog: `%PKT_INFRA-LINK-3-UPDOWN: Interface GigabitEthernet0/0/0/1, changed state to Down`
- BFD flaps on core-facing interface
- Downstream branch sites reported intermittent packet loss (5–12%) during convergence windows
- Route churn visible in Kentik flow analysis

## Root Cause

Degraded SFP transceiver on ISP-A's PE router caused intermittent CRC errors and link-layer drops. Once error rate exceeded BFD detection threshold, sessions flapped. The issue was on the far-end (ISP-A side), not on xr-43.

## Resolution Steps

1. Confirmed xr-43 interface optics within spec (`show controllers optics 0/0/0/1`)
2. Observed CRC input errors incrementing (`show interfaces GigabitEthernet0/0/0/1`)
3. Engaged ISP-A NOC with evidence of far-end CRC errors
4. ISP-A replaced degraded SFP on their PE
5. Monitored 15 minutes post-fix — zero CRC errors, BGP stable

## Impact

- Duration: 47 minutes (08:22–09:09 UTC)
- Traffic impact: Minimal — BFD fast-failover to xr-44 maintained connectivity
- Route churn caused ~200ms of elevated latency for 6 branch sites during each flap event

## Lessons Learned

- Far-end optic degradation is invisible to local SNMP polling until it causes link events
- Consider adding proactive optical power monitoring via NETCONF/gNMI streaming telemetry
- BFD + ECMP failover worked as designed — no topology changes needed
